# AI Job Market Intelligence Platform：任务拆分与当前进度

更新时间：2026-08-25

本文记录当前已经完成的工作、验证结果、剩余任务和验收标准。当前工作重点是
“多来源岗位数据平台”，还没有开始简历匹配、自然语言推荐和用户求职流程产品。

## 1. 当前数据链路

```text
JobSpy 多来源抓取
  → NormalizedJob 第三方边界标准化
  → CanonicalJobInput 平台业务标准化
  → 去重、幂等、快照和数据库写入
  → 岗位分类、技能标签、地点层级和薪资换算
  → job.v3 / job-page.v3 / job-facets.v2 API
```

## 2. 已完成任务

| 数据库迁移 | 已完成 | 已有 0001–0006 迁移，包含岗位表、自动采集、分类、地点层级和废弃字段兼容标记。 |
| 数据 API | 已完成 | 支持列表、详情、城市/省州/国家筛选、技能筛选、薪资筛选和实时 facets。 |
| API Schema | 已完成 | 当前公开契约为 `job.v3`、`job-page.v3`、`job-facets.v2`。 |
| 中文技术文档 | 已完成 | 已形成数据接口、JobSpy 集成、字段分类和展示规范文档。 |

## 3. 当前完成质量

### 已实际验证

- 数据库当前有 25 条岗位数据。
- 25 条岗位均具备国家、省/州和城市地点结构。
- 25 条岗位的 `classification_version` 均为 3。
- 真实 JobSpy 新岗位写入成功：`created=1`。
- 同一查询重复执行成功幂等：`created=0, unchanged=1`。
- API 契约检查通过：`job-page.v3`、`job.v3`、`job-facets.v2`。
- API 响应不再暴露岗位级别、教育程度和经验年限字段。
- Ruff、compileall 和 17 项自动化测试通过。

### 目前属于“已实现但需要扩大验证”的部分

- Indeed 已完成真实抓取验证；其他来源虽然已接入配置和适配器，但还需要分别做真实请求、字段空值率和反爬失败验证。
- 调度、断点和重试逻辑已有实现与单元测试，但还需要在真实 worker、网络失败和进程中断场景下做长时间测试。
- 去重规则已在小规模数据上验证，还需要构造跨来源同岗位、同公司不同岗位、不同地点同名岗位等数据集进行误合并率测试。
- API 查询已通过 Repository 契约检查，还需要前端联调和并发/大数据量性能测试。

### 已明确不做的字段

岗位级别、教育程度和经验年限不属于当前产品字段。相关旧数据库列只做兼容保留，
新抓取不写入，API、Facets、Schema 和展示文档均不使用。

## 4. 剩余任务

### P0：把岗位数据平台做成可稳定运行的后端基础设施

- [ ] 为每个真实来源完成抓取验收：成功率、限流、超时、字段填充率、重复率。
- [ ] 建立采集运行监控：每次运行的 fetched/created/merged/unchanged/failed、来源耗时和错误摘要。
- [ ] 建立数据质量指标：地点完整率、薪资公开率、JD 完整率、技能标签覆盖率和重复岗位率。
- [ ] 完成 worker 进程中断、数据库断连、来源超时和重复 worker 并发测试。
- [ ] 为 4 小时任务增加告警和失败重试上限通知。
- [ ] 使用真实规模数据执行 PostgreSQL `EXPLAIN ANALYZE`，确认游标分页、地点筛选、技能筛选和 facets 索引效果。
- [ ] 补充数据保留策略、原始 JD 合规策略和各招聘网站访问频率限制说明。
- [ ] 处理城市标准 ID、时区、远程岗位无城市和多地点岗位等长尾地点情况。

### P1：搜索和市场分析

- [ ] 增加全文搜索和后续向量检索；结构化筛选与语义检索需要并行支持。
- [ ] 建立按天/周/月的岗位数量、技能热度、地区分布和公司活跃度汇总表。
- [ ] 增加趋势 API 和市场分析页面所需的数据接口。

### P1：前端职位浏览体验

## 5. 建议验收顺序

1. 先完成所有来源的真实抓取与数据质量报告。
2. 再完成调度、断点、重试和跨来源去重的故障测试。
3. 再完成职位列表/详情页和国家、省州、城市级联筛选。
4. 再实现全文搜索、自然语言搜索和市场趋势 API。
5. 最后接入简历匹配、技能差距分析和求职流程管理。
